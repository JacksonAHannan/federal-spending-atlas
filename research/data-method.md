# USAspending and district geography

Verified November 21, 2026. Firecrawl had no remaining credits; official documentation was read through the web tool and structured API data fetched directly.

[API contract](https://github.com/fedspendingtransparency/usaspending-api/blob/master/usaspending_api/api_contracts/contracts/v2/search/spending_by_geography.md) defines `spending_level: transactions` as the transaction grouping. The app requests `scope: place_of_performance`, `geo_layer: district`, `spending_level: transactions`, fiscal-year start/end dates, and disjoint award type lists for contracts (A–D) and grants (02–05). Raw envelopes preserve these request bodies and the complete response. Negative amounts are retained.

[Endpoint source](https://github.com/fedspendingtransparency/usaspending-api/blob/master/usaspending_api/search/v2/views/spending_by_geography.py) selects `congressional_cur_agg_key` for district geography. A retrieved copy is preserved as `geography-endpoint.py`. Thus district identifiers are derived current identifiers; they are not originally submitted or original-year geography. [Search filter documentation](https://github.com/fedspendingtransparency/usaspending-api/blob/master/usaspending_api/api_contracts/search_filters.md#standard-location-object) defines `district_current`; live category queries use it rather than `district_original`.

[Census cartographic boundary file](https://www2.census.gov/geo/tiger/GENZ2025/shp/cb_2025_us_cd119_500k.zip) contains 441 unique four-digit GEOIDs for the 119th Congress: 435 voting districts and six delegate/resident-commissioner areas. GeoIDs join exactly to the 441 nonempty identifiers returned in every saved API response. A blank identifier appears separately in each response. This join alone does not establish the accuracy of every underlying transaction's geocoding. Current-identifier historical reassignment, regional place-of-performance conventions, and redistricting remain limitations.

The API defaults domestic place of performance for district geography. The app does not reconstruct nationwide federal spending outside the returned district result set. Unmatched/blank rows are retained separately, excluded from map totals, and exported with `row_type: unmapped` only for nationwide CSVs. A small excluded aggregate is not evidence that all federal spending can be precisely allocated to districts.

Per-capita figures are calculated from the amount and API-returned population rather than combining already-rounded API per-capita numbers. The response does not label population vintage; these are reference populations, not yearly demographic estimates. All amounts are nominal dollars.

Verification: all ten raw results reconcile exactly to matched district rows plus excluded rows using Decimal. The independent original FY2025 combined grant/contract probe reconciles to the sum of the two saved type-group responses within two cents per row (API floating-point output rounding). All 441 GEOIDs join; no territorial code is silently converted to 00. DC and territorial 98 identifiers are retained as submitted.

[Category API contract](https://github.com/fedspendingtransparency/usaspending-api/blob/master/usaspending_api/api_contracts/contracts/v2/search/spending_by_category.md) supports awarding_agency, cfda, and naics. On demand the browser requests the top six in each relevant category using the same year, type, and current-district filters. CORS behavior was verified from a real browser. CFDA applies to grant programs; NAICS is an industry classification for contracts, not a grant program. The lists are labeled accordingly and are not full category reconciliations. They may reflect a newer upstream revision than saved map totals.
